# Policy 14: Use of Generative AI Tools at Work

Harbor Pay, Inc. · Owner: Information Security · Effective 1 October 2026 · Review annually

## 1. Purpose

Generative AI tools can speed up writing, coding and analysis, and many of us already use them. This policy exists so that we get that benefit without sending customer data, source code or confidential plans to services we do not control, and so that work produced with these tools is still work we can stand behind.

## 2. Scope

This policy applies to all employees, contractors and interns of Harbor Pay, on any device, when the work is for the company. It covers chat assistants, code completion, image and audio generators, and any feature of another product that sends content to a model, whether or not the tool is described as "AI".

## 3. Rules

- Use only the tools on the approved list in section 4. Use of a generative AI tool that is not on the list for company work is not permitted; request an addition through the security portal and expect an answer within ten business days.
- Do not enter customer personal data, payment data, credentials, unreleased financial results or source code into any AI tool other than the enterprise instances marked "internal data allowed" in the approved list.
- Review and take responsibility for everything a tool produces before it leaves your hands. AI-generated code is reviewed like any other code; AI-generated text that goes to customers or regulators is approved like any other text.
- Disclose material use of AI assistance in design documents, external publications and any deliverable where the recipient would reasonably want to know.
- Do not use AI tools to make or support decisions about hiring, promotion or discipline.

## 4. Approved tools

| Tool | Internal data allowed | Notes |
|---|---|---|
| Harbor Assist (enterprise) | yes | company instance, no training on our data |
| Harbor Code (IDE plugin) | yes, source code only | |
| Public chat assistants | no | public information only |

## 5. Reporting

If you believe confidential data has been entered into an unapproved tool, report it to security@example.org the same day. Reporting promptly is never held against you; failing to report is a policy violation.

Questions about this policy go to the Information Security team. Previous version: Policy 14 rev. 1, 15 March 2025.
